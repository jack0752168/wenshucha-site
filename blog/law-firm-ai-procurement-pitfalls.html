律所采购 AI 系统的 5 个坑:SaaS / 数据 / 模型 / 工具链 / 服务期(2026)

2026-06-14 · 文书查 · 面向律所采购委员会与信息化主任

法律 AI 这两年从「要不要上」变成了「上哪家」。但律所采购委员会真正坐下来对比方案时,会发现各家说辞高度雷同——都号称「上亿裁判文书」「自研法律大模型」「私有化部署」。问题是,这些词的水分,签约前看不出来,上线后才疼。本文把律所采购法律 AI 最容易踩的 5 个坑逐个拆开,并给一份能在一轮会上问出谁有真货的采购对照清单。它不替代你的尽调,但能帮你把对的问题问在签约之前。

坑一:把 SaaS 当私有化买

这是最贵的一个坑,因为它踩下去时你往往毫无察觉。很多供应商会说自己「支持私有化」,但落到合同里,交付的其实是一个把界面装在你内网、推理却调外部大模型 API 的混合方案——你输入的案情,仍然出了内网。

对律所来说,判据只有一条:当事人材料、案件底稿、内部文书,能不能完全不离开律所机房?对于承接涉密案件、政府国企客户、跨境业务的所,委托协议普遍写明数据不得出域、不得交由第三方处理。这类业务一旦走了 SaaS 或「伪私有化」,轻则违约,重则触碰《数据安全法》《个人信息保护法》对敏感数据出境的红线。

怎么识破:直接问三句——①模型推理跑在哪台机器上?②系统运行时是否需要连任何外网?③能不能在断网环境里完整演示一遍?只要有一句答得含糊,所谓「私有化」就要打问号。真正的本地离线 AI,断网照跑。

坑二:数据只看「多少亿条」,不看口径

「我们有 1.5 亿+ 裁判文书」听起来很唬人,但条数是最容易注水的指标。同样宣称上亿条,有的是去重后、结构化的全量库,有的是把同一篇文书在不同页面重复抓取的原始网页堆叠。律师真正用起来,差距是天壤之别。

评估数据底座,要问的是这四件事,而不是一个总数:

维度该问什么注水的样子
覆盖范围刑事/民事/行政/执行/国家赔偿是否齐全?能否给出按案由、地域、年份的分布?只给一个总数,拿不出分布,某些案由或近年数据其实是空的
来源合法是否源自人民法院公开渠道?每篇能否回链到原始文书?来源说不清,无法溯源,合规汇报时过不了关
结构化案号/法院/案由/当事人/裁判结果是否抽成稳定字段?只有一坨纯文本,检索、统计、引用都做不了
更新机制多久同步一次?私有化环境下怎么离线更新?交付时是一次性快照,之后数据永远停在采购那一天

一句话:条数证明不了什么,口径才决定数据能不能用。要求供应商现场展示一次按案由+地域+年份的数据分布,注水库通常当场就露馅。

坑三:模型分不清「自研微调」还是「套壳通用」

几乎所有供应商都说自己有「法律大模型」。但其中相当一部分,是在通用大模型外面套了个提示词,本质是调用外部 API 的「套壳」。这类模型有两个致命问题:一是引用法条爱编(法条号、案例张冠李戴,对律师是硬伤);二是不能真正私有化(底层依赖外部 API,断网就废)。

分辨方法很简单——让供应商用你本所的真实案情现场提问,盯三点:

  • 引用是否可核:它给的法条、司法解释、案例,能不能一条条核对真实存在?套壳模型常一本正经地编。
  • 能否溯源:每个结论能不能给出可点开的原始文书链接?不能溯源的法律 AI,律师不敢用。
  • 能否吃本所卷宗:能不能用本所历史案件二次微调,形成别家没有的专属能力?套壳模型做不到。

再补一句直球:「模型跑在哪?」如果回答是「调用某外部大模型 API」,那它既不是真自研,也无法真私有化,坑一和坑三其实是同一个。

坑四:只买了数据和模型,律师却用不起来

这个坑很隐蔽:数据合规、模型也能跑,验收时一切正常,但系统上线三个月后就没人打开了。原因是缺了工具链——律师每天真正用的不是「大模型」,而是大模型之上的那层应用。

一套能落地的律所 AI,数据和模型只是底座,上面必须有:

工具链能力律师用它干什么
类案检索输入案情,秒级找到相似已决案件,看法院怎么判
判决要素抽取从一批案例里自动抽出争议焦点、裁判理由、赔偿金额
胜诉率 / 赔偿区间预测给当事人一个有数据支撑的预期,而非「凭经验」
文书辅助起草基于类案与本所模板生成初稿,律师改而非从零写
律师工作台 UI + 系统对接在熟悉的界面里用,能与现有办案 / 案管系统打通

只买数据和模型、没有工具链,等于买了发动机却没有整车。采购时要把工具链清单写进需求,验收时一定让一线律师实际试用、而不是只看供应商演示——能不能用得顺,只有真用的人知道。

坑五:只看签约价,不看服务期

法律 AI 不是买断即结束的软件。裁判文书与法规每天在更新,模型在迭代,律所会不断提新需求,系统也需要有人维护。只盯签约那一笔价、不谈服务期,很容易第二年发现:数据停在一年前、模型还是旧版、出了问题找不到人。

把全生命周期成本算清楚,合同里这几条必须写明:

  • 数据同步:多久更新一次?私有化环境怎么离线导入?是否额外收费?
  • 模型升级:服务期内是否含版本迭代?升级是否要停机?
  • 响应时效:出 bug 多久响应、多久修复?有没有明确 SLA?
  • 定制需求:服务期内包多少定制开发?超出怎么计价?
  • 续费口径:服务期满后续费多少?数据与模型的所有权 / 使用权归谁?

一个常见的反面案例:签约价压得很低,但服务期只含一年、数据不含同步,第二年续费和数据更新单列报价,总成本反而更高。算账要算三年,不是算签约那一天。

把五个坑变成一张采购清单

把这份清单发给每一家候选供应商,一轮就能问出谁有真货:

  1. 私有化:模型推理在哪跑?运行需不需要连外网?能否断网完整演示?
  2. 数据:覆盖哪几类文书?能否现场展示按案由+地域+年份的分布?每篇能否溯源?私有化下怎么更新?
  3. 模型:自研微调还是套壳?用本所真实案情现场试,引用是否可核、可溯源?能否用本所卷宗二次微调?
  4. 工具链:含哪些应用(类案检索/要素抽取/预测/起草/工作台)?能否与现有办案系统对接?让一线律师试用了吗?
  5. 服务期:数据同步频率?模型升级是否含?bug 响应 SLA?定制需求额度?续费与使用权口径?
  6. 交付:是否先出演示 demo 再签约?demo 阶段是否收费?交付周期多久?

这六组问题,覆盖了从签约到三年运行的全部关键变量。真有货的供应商会乐意逐条作答;含糊其辞、绕开问题的,基本可以排除。

常见问题

Q:我们所规模不大,有必要这么较真吗?

A:越是预算有限,越要把钱花在刀刃上。一次选错供应商,沉没的不只是采购款,还有律师重新适应系统的时间成本和信任成本。这份清单不增加你的工作量,只是把该问的问题问在签约之前。

Q:能不能先小范围试用再全所采购?

A:强烈建议。先从一个业务部门(如劳动争议、合同纠纷)或一个办公室起步,用真实案件跑出效果,再决定是否全所推广。正规供应商通常提供不收费的演示 demo,demo 跑通、合伙人认可后再签合同,能大幅降低决策风险。

Q:私有化部署是不是一定比 SaaS 贵?

A:首次投入确实高于按月订阅,但对承接敏感案件的律所,合规与数据安全是不能让步的底线。算上「用 SaaS 一旦泄露的赔偿与声誉损失」,私有化的总成本反而更低。详见 律所 AI 投资回报测算。
