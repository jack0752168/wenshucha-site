为什么做成 MCP

法律数据接入 AI 的老办法是：申请 API key、读文档、写对接代码、处理分页与鉴权，最后还要自己把结果喂给模型。

MCP 把这一整段全省掉。你在支持 MCP 的客户端里粘一段配置，然后直接用中文问——「查一下民间借贷里保证人承担连带责任的判决，找 3 个」——模型会自己选工具、自己构造检索词、自己把带案号的真实判决拿回来。

更关键的是反幻觉这件事只有在 MCP 里才做得顺：模型写完一段引用后，可以立刻自己调核验工具确认案号和判词是真的，不需要你人工回查。

四个工具

search_judgments

在 1.6 亿条记录的标题与库内正文中检索，返回案号、标题、法院、裁判日期与命中片段。

可按年份区间、法院名称、省份收窄；分页上限每页 50 条。

get_judgment

按案号取库内正文。案号全角半角括号都能识别。

同一案号有多条记录时，会在全部命中记录中按正文长度排序，优先返回较完整的一条。

verify_case_number反幻觉

核验一个案号是否真实存在。存在则返回标题、法院、裁判日期，作为可追溯的凭证。

用来堵大模型编案号——它编出来的案号，这里查不到。

verify_quote反幻觉

核验一段判词能否以分词后的连续短语命中库内正文，可锁定到某一案号，回答「这段话真的是这个案子里说的吗」。

核查法律意见书、代理词里的引用有没有被改写或杜撰。这个工具需要判决正文才做得了，只有摘要的产品做不出来。

检索方式：如实说明

本服务是精确词汇检索（BM25），不是向量语义检索。

意味着查询词要用简体中文的法律术语。实测：「拖欠劳动报酬」711,408 条，口语说法「老板不发工资」只有 7,965 条（少约 89 倍）；繁体「經濟性裁員」是真的 0 条。

但在 MCP 场景下这基本不用你操心——调用方本身就是大模型，工具描述里已写明改写规则，模型会自动把口语改写成法律术语再检索。

相比向量召回，这样做的好处是绝大多数结果都能追溯到具体案号（案号字段覆盖约 97.8%），不会出现「看起来相关、实际不是那个案子」的情况。做法律场景，可追溯比召回率更重要。

常见问题

MCP 是什么？为什么法律数据要做成 MCP？

MCP（Model Context Protocol）是让大模型调用外部工具与数据的开放协议。做成 MCP 之后，你在 Claude、Cursor、Claude Code 里直接用自然语言提问，模型会自己调用检索工具并把带案号的真实判决拿回来，不需要另外写代码对接 API，也不需要把判决书复制粘贴进对话框。

支持语义检索吗？

不支持向量语义检索，是精确词汇检索。但 MCP 场景下调用方就是大模型，它会自动把口语改写成法律术语，效果接近语义搜索，且每条结果可追溯案号。确实需要纯向量召回的，可针对特定语料单独定制。

免费的和付费的功能有区别吗？

没有。所有档位四个工具全部可用，数据范围都是全量 1.6 亿条记录不限子集，档位之间只差调用次数、全文篇数和速率。连接服务、拉取工具列表、参数错误、未知工具名、服务端故障均不计次。
